# ADR-004: LLM-шлюз на Microsoft.Extensions.AI та офіційних SDK

- Статус: прийнято
- Дата: 2026-11-01
- Автор рішення: Садиков Константін

## Контекст

FR-002 вимагає передати запит шукача роботи до API обраної LLM і повернути текстову відповідь або список вакансій; FR-010 — аналіз конкретних вакансій. REL-003 і PERF-002 обмежують очікування 30 секундами, а відмова LLM не повинна блокувати решту застосунку. THR-06 забороняє передавати зовнішній LLM email, ім'я чи `user_id` (маскування виконується до шлюзу), THR-09 — тримати ключі в репозиторії, THR-10 — вичерпувати ліміт тарифу без обмежень на боці API.

Потрібен один інтерфейс для чату, потокової відповіді та структурованого витягу фільтрів (JSON-схема), який працює з кількома постачальниками: OpenRouter як основний (дешевий доступ до багатьох моделей), прямі OpenAI та Anthropic як резерв, а також OpenAI-сумісні Gemini й локальний Ollama для розробки. Порядок провайдерів і моделі мають змінюватися конфігурацією, без перезбирання коду, а відсутність ключів не повинна заважати запуску (REL-003).

## Рішення

1. **Абстракція — `Microsoft.Extensions.AI.IChatClient`.** Сервіси AI працюють лише з `IChatClient` і `ChatOptions`; конкретний провайдер їх не цікавить. Це дає стандартні `GetResponseAsync<T>` для структурованого виводу та `GetStreamingResponseAsync` для SSE.
2. **Офіційні SDK.** Тип `OpenAiCompatible` створює `OpenAIClient` з власним `Endpoint` і моделлю (`GetChatClient(model).AsIChatClient()`); тип `Anthropic` — офіційний `AnthropicClient` (`AsIChatClient(model)`). Власний HTTP-клієнт не пишемо.
3. **Ланцюжки в конфігурації.** Секція `Llm:Roles:<Extract|Chat|Analyze>:Chain` задає впорядкований список `{ Provider, Model }`; `Llm:Providers:<name>` — тип, `BaseUrl` і `ApiKeyEnv`. Резервування лише на таймаут спроби, HTTP 429, 5xx або збій мережі; 400/401/403 повертаються одразу, бо це наша помилка або неправильний ключ. У потоці перемикання можливе тільки до першого відданого фрагмента, щоб не зшивати текст двох провайдерів.
4. **Бюджет часу.** `AttemptTimeout` (12 с) обмежує одну ланку, `TotalTimeout` (30 с) — весь ланцюжок (REL-003, R-2). Автоматичні повторні спроби SDK вимкнено (`MaxRetries = 0`), інакше резервування й таймаути стають непередбачуваними.
5. **Секрети й приватність.** Ключ читається зі змінної середовища, названої в `ApiKeyEnv`, або з `Llm:Providers:<name>:ApiKey` у User Secrets / змінних середовища; у `appsettings.json` ключів немає (THR-09). Журналюються лише роль, провайдер, модель, статус і тривалість, ніколи — запит або відповідь (THR-06, THR-08). Zero Data Retention для OpenRouter вмикається в налаштуваннях приватності акаунта (не в коді) і має бути частиною інструкції розгортання.
6. **Старт без ключів.** Відсутній ключ лише виключає ланку з ланцюжка з попередженням у журналі; роль без жодної придатної ланки кидає `LlmUnavailableException(NotConfigured)` під час використання, а не на старті (REL-003). Структурні помилки (невідомий тип, невідомий провайдер, неабсолютний `BaseUrl`, некоректні таймаути) відхиляються `ValidateOnStart`.

## Розглянуті альтернативи

- **Semantic Kernel.** Відхилено: це оркестрація агентів, планувальників і плагінів, а нам потрібні chat completions, структурований вивід і простий ланцюжок резервування. Зайвий шар збільшує залежності та поверхню змін між версіями.
- **Microsoft Agent Framework.** Відхилено: агентний рантайм із власним життєвим циклом не дає нічого для одного запиту «текст → відповідь/фільтри», а його API ще змінюється.
- **LiteLLM sidecar.** Відхилено: окремий сервіс треба розгортати, моніторити й захищати, ключі переїжджають у його конфігурацію (THR-09), а Python-рантайм додає хоп і затримку до 30-секундного бюджету.
- **Власний HTTP-клієнт до кожного API.** Відхилено: довелося б самостійно підтримувати SSE-парсинг, формати помилок, повторні спроби та зміни схем; офіційні SDK роблять це краще й уже віддають `IChatClient`.

## Наслідки

+ Один `IChatClient` для чату, аналізу й витягу фільтрів; зміна провайдера або моделі — лише конфігурація.
+ API стартує без ключів і без мережі; відмова LLM ізольована за 30 с і не блокує каталог (REL-003, R-2).
+ Ключі не потрапляють у Git; журнали не містять тексту діалогу.
− Версії SDK і `Microsoft.Extensions.AI` треба узгоджувати під час оновлень.
− Резервування не рятує від 400/401/403 (свідомо) і не відновлює потік після першого фрагмента.
− Zero Data Retention на OpenRouter залежить від налаштувань акаунта, а не від коду; це вимога до розгортання.
