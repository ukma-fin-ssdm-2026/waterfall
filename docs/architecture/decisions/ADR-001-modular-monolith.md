# ADR-001: Модульний моноліт замість мікросервісів

- Статус: прийнято
- Дата: 2026-09-25
- Автор рішення: Денис

## Контекст

Команда з 4 осіб, архітектурний зріз — Lab 3 (повний застосунок — до кінця семестру), навантаження каталогу помірне (PERF-001: 100 одночасних користувачів). Мікросервіси дають незалежне масштабування ціною мережевої складності, окремих деплоїв і міжсервісних контрактів.

## Рішення

Clean / Layered Architecture в одному процесі: .NET MAUI клієнт → Core Services → Repository Layer. Збір вакансій — `BackgroundService` всередині процесу (§3.4.1), без окремих воркерів.

## Розглянуті альтернативи

- **Мікросервіси (Auth, Catalog, Parser, Analytics як окремі деплої).** Відхилено: мережеві хопи між сервісами загрожують PERF-001 (<1 с p95), а оркестрація, контракти й distributed tracing — надлишкові для команди з 4 осіб. Межі модулів уже проведено так, щоб Parser можна було винести окремо без переписування (§3.4).
- **Event-Driven архітектура (Kafka/RabbitMQ).** Відхилено: ключові операції (пошук, збереження, консультація ШІ) — синхронні request-response; брокер додає eventual consistency (ризик порушення REL-002 при збереженні) та адміністрування черг заради одного фонового потоку, який закриває `BackgroundService`.
- Повне порівняння — [`../high-level-design.md`](../high-level-design.md) §1.1.

## Наслідки

+ Один деплой, DI-виклики замість мережі, REL-003 ізоляція модульними межами.
− Вертикальне масштабування; винесення Parser в окремий сервіс — зарезервовано, межа вже проведена (§3.4).
