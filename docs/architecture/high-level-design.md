# Високорівнева архітектура проєкту Waterfall

## 1. Архітектурний стиль
Обраний архітектурний стиль: **Модульний моноліт (Clean / Layered Architecture) з інтегрованим фоновим сервісом збору даних (Background Service у .NET)**.

**Обґрунтування вибору:**
- Вся система розробляється на єдиному, надійному та типобезпечному стеку **C# (.NET)**. Це спрощує розробку, усуває накладні витрати на підтримку двох різних мов і рантаймів (повна відмова від Python на користь нативних бібліотек .NET) та забезпечує повну сумісність компонентів.
- Модульна трирівнева структура чітко розмежовує клієнтський рівень (.NET MAUI), рівень бізнес-логіки (Core Services) та рівень доступу до даних (Repository Layer).
- Збір та парсинг вакансій із зовнішніх ресурсів реалізовано як компонент рівня репозиторію/даних (Job Parser Service). Він працює як керований фоновий процес з дотриманням лімітів запитів і передає дані напряму до нормалізації та збереження через EF Core без потреби в окремих серверах-воркерах.
- Інтеграція з зовнішніми ШІ та сайтами пошуку роботи ізольована у відповідних сервісах, що забезпечує гнучкість та легку заміну провайдерів або джерел даних.

## 3. Опис інтерфейсів

### 3.1. Інтерфейси (API) між архітектурними шарами та компонентами
- **Client Application (.NET MAUI через HTTP Gateway Service) ↔ Core Services Layer (C#):**
  - **Протокол:** HTTPS / REST API. 
  - **Функція:** Клієнт відправляє запити на отримання списку вакансій, фільтрацію, збереження вакансій ("лайки") та взаємодію з ШІ. Відповіді повертаються у форматі JSON. Шар сервісів має вбудоване In-Memory кешування для швидкої видачі сторінок (< 1 сек) і забезпечує безшовну роботу як з локальним середовищем, так і з продакшн-сервером.
- **Core Services Layer ↔ Repository Layer (Data Access):**
  - **Протокол:** Внутрішні виклики (C# Interfaces / Dependency Injection).
  - **Функція:** Забезпечує чистий доступ до бази даних. Викликається кор-сервісами для отримання актуальних даних (у разі відсутності в кеші) або для збереження нових сутностей у базі.
- **Repository Layer ↔ Relational Database (MSSQL for server, SQLite for local use):**
  - **Протокол:** TCP/IP або звернення до локального файлу (через Entity Framework Core). 
  - **Функція:** Надійне персистентне збереження та зчитування профілів користувачів, нормалізованих вакансій, аналітичної статистики, пошукових запитів та історії взаємодії з ШІ.
- **Job Parser Service ↔ Job Ingestion & Normalization Service (усередині Repository Layer):**
  - **Протокол:** Внутрішні виклики (C# Interfaces / Dependency Injection). 
  - **Функція:** Парсер передає зібрані сирі структури вакансій. Сервіс нормалізації обробляє їх, очищає, приводить до єдиного формату та повертає вже повністю підготовлені дані для збереження в БД та інвалідації кешу.
- **Job Parser Service (Repository Layer) ↔ Сайти пошуку роботи (Work.ua, Robota.ua, Djinni):**
  - **Протокол:** HTTPS (GET-запити через .NET `HttpClient`).
  - **Функція:** Отримання відкритих HTML-сторінок із майданчиків працевлаштування для подальшого вилучення та структурування вакансій.
- **Core Services Layer ↔ LLM API (External):**
  - **Протокол:** HTTPS / REST API (OpenAI, Gemini тощо).
  - **Функція:** Відправка промптів (контекст запиту та відібраних вакансій) через AI Consultant Service та отримання відповідей для користувача.

### 3.2. Клієнтський шар (.NET MAUI Client Application)
- **HTTP Gateway Service:**
  - **Призначення:** Централізований мережевий шлюз у клієнтському .NET MAUI застосунку (C#). Відповідає за конфігурацію HTTP-клієнта (`HttpClient`), автоматичну підстановку токенів автентифікації (`Authorization: Bearer <JWT>`), глобальну обробку помилок і статусів відповідей (401, 403, 500) та надійний обмін даними між UI-компонентами (XAML / MVVM) і бекендом.

### 3.3. Внутрішні сервіси та інтерфейси Core Services Layer
Усі внутрішні сервіси взаємодіють між собою через механізм **Dependency Injection (C# Interfaces)** у межах єдиного процесу бекенду:

1. **Authentication Service (Сервіс аутентифікації):**
   - **Призначення:** Управління обліковими записами користувачів (шукачів роботи та роботодавців/аналітиків), реєстрація, автентифікація, генерація та перевірка JWT-токенів сесій.
   - **Інтерфейс / Взаємодія:**
     - Звертається до `Security Service` для хешування та верифікації паролів.
     - Звертається до `Storage Service` для зчитування облікових даних та створення профілів.
2. **Cache Service (Сервіс кешування):**
   - **Призначення:** Керування In-Memory кешем, збереження часто запитуваних списків вакансій та результатів фільтрації для досягнення цільової швидкодії пагінації (< 1 сек). Відповідає за логіку збереження, життєвого циклу (TTL) та інвалідації/оновлення кешу.
   - **Інтерфейс / Взаємодія:**
     - Викликається `Storage Service` для швидкої перевірки та отримання кешованих вакансій перед запитом до БД (патерн Cache-Aside).
     - Викликається при надходженні нових вакансій для скидання застарілого кешу видачі.
3. **Storage Service (Сервіс збереження та доступу до даних):**
   - **Призначення:** Централізована робота з сутностями системи. Відповідає за бізнес логіку, за збереження та видачу вакансій за фільтрами, управління вподобаннями ("лайками"), збереження профілів користувачів та історії взаємодії з ШІ.
   - **Інтерфейс / Взаємодія:**
     - Звертається до `Cache Service` для читання та оновлення кешованих даних.
     - Звертається до `Repository Layer` (EF Core) для виконання персистентних операцій у базі даних (MSSQL/SQLite).
     - Надає методи доступу до даних для `Analytics & Statistics Service`, `AI Consultant Service` та контролерів пошуку.
4. **Analytics & Statistics Service (Сервіс аналітики та статистики):**
   - **Призначення:** Обробка бізнес-аналітики та алгоритмічного відбору. Відповідає за персоналізований підбір вакансій на основі вподобань користувача, формування ринкової аналітики (тренди, заробітні плати, затребувані навички для роботодавців/аналітиків) та особистої статистики пошукача.
   - **Інтерфейс / Взаємодія:**
     - Отримує сирі дані про вакансії, відгуки та лайки через `Storage Service`.
     - Зберігає розраховані агреговані статистичні звіти у `Cache Service` для уникнення повторних важких обчислень.
     - Надає дані клієнтському додатку для статистики, аналітики та списку рекомендованих пропозицій.
5. **AI Consultant Service (Сервіс ШІ-консультанта):**
   - **Призначення:** Інтерактивний діалоговий помічник для пошукача та роботодавця. Обробляє запити природною мовою, формує релевантний контекст (промпти) на основі вакансій або резюме, веде історію діалогів та надсилає запити до зовнішніх мовних моделей.
   - **Інтерфейс / Взаємодія:**
     - Отримує контекст вакансій і користувацькі профілі через `Storage Service`.
     - Зберігає історію листування з користувачем через `Storage Service`.
     - Виконує зовнішні HTTP-запити до `LLM API` (Google Gemini / OpenAI).
     - Надає API для віджету чату на фронтенді (через HTTP Gateway Service).
6. **Security Service (Сервіс безпеки даних):**
   - **Призначення:** Реалізація нефункціональних вимог безпеки (NFR) — криптографічний захист, хешування конфіденційних даних та шифрування чутливих параметрів.
   - **Інтерфейс / Взаємодія:**
     - Забезпечує криптографічно стійке хешування паролів.
     - Виконує шифрування/дешифрування чутливих даних (API-ключі зовнішніх ШІ-провайдерів, конфіденційні конфігурації).
     - Надає інтерфейс для `Authentication Service` та інших бізнес-сервісів.

### 3.4. Сервіси та інтерфейси Repository Layer (рівень даних)
1. **Job Parser Service (Сервіс збору та парсингу вакансій):**
   - **Призначення:** Асинхронний збір даних із зовнішніх відкритих ресурсів (Work.ua, Robota.ua, Djinni) засобами C# (.NET `HttpClient`, HTML-парсери). Працює як керований фоновий сервіс (`BackgroundService`) з контролем лімітів запитів.
   - **Інтерфейс / Взаємодія:**
     - Виконує зовнішні HTTPS GET-запити до сайтів пошуку роботи.
     - Передає отримані структури даних безпосередньо до `Job Ingestion & Normalization Service`.
2. **Job Ingestion & Normalization Service (Сервіс нормалізації та підготовки даних):**
   - **Призначення:** Приймає структуровані сирі дані від `Job Parser Service`, конвертує та нормалізує формати зарплат (до єдиної валюти/шкали), уніфікує назви міст і стеків технологій, відсіює дублікати й повертає повністю підготовлені та валідовані доменні сутності вакансій.
   - **Інтерфейс / Взаємодія:**
     - Приймає внутрішній потік даних від `Job Parser Service` (через Dependency Injection).
     - Передає вже підготовлені сутності безпосередньо до EF Core репозиторіїв для запису в БД.
     - Ініціює оновлення/скидання кешу у `Cache Service`.
3. **Data Repositories (EF Core Repositories):**
   - **Призначення:** Інкапсулюють прямі запити до реляційної бази даних через Entity Framework Core (підтримка як серверної MSSQL, так і локальної SQLite).
