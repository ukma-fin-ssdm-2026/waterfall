## 3. Плани рівнів тестування (Testing Pyramid & Scope)

### 3.1. Інтеграційні тести (Integration Tests)
- **Routing Pipeline:** Перевірка повного наскрізного ланцюжка: HTTP-запит → JWT Authentication Middleware → Correlation/Request ID Scope → Model Validation Filter → Controller → Service → Repository → SQLite.
- **Конвеєр збору даних (Ingestion Pipeline):** Наскрізна інтеграція без підробок: симуляція надходження сирого JSON-файлу у тимчасову директорію → фоновий `JobParserService` → нормалізація через `VacancyIngestionService` → пакетний `BulkUpsertAsync` у SQLite. Перевірка коректності оновлення існуючих записів, дедуплікації та збереження дати першої появи (`CreatedAt`).

### 3.2. Системні / E2E тести (System & End-to-End Tests)
- **Клієнтський рівень (MAUI Desktop Client E2E):** Тестування взаємодії `waterfall.Client` з працюючим тестовим екземпляром API: збереження токена авторизації, пагінація вітрини вакансій, реактивне оновлення списку збережених вакансій між ViewModel.

### 3.3. Приймальні тести (Acceptance Testing / BDD)
Автоматизація критеріїв успішності користувацьких історій з [`user-stories.md`](../requirements/user-stories.md) у форматі Given-When-Then:
- **US-01 (Пошук та фільтрація):** *Given* у каталозі присутні 100 вакансій із різними стеками та зарплатами, *When* шукач вводить запит "C# remote" з діапазоном 40 000 – 70 000 грн, *Then* повертаються виключно релевантні записи, розбиті на сторінки по 10 елементів.
- **FR-001 (Стійкість імпорту):** *Given* JS00ON-дамп із 80 валідними та 20 пошкодженими записами (відсутній заголовок, некоректні дати), *When* парсер обробляє файл, *Then* 80 вакансій успішно потрапляють у базу, а 20 відхилених записуються у лог із деталізацією помилки без падіння сервісу.


## 4. Спеціалізовані плани тестування

### 4.1. Тестування продуктивності (Performance & Load)
- **PERF-001 (Час відповіді каталогу ≤ 200 мс):** Навантажувальне тестування ендпоінта `/api/v1/vacancies` інструментом k6 (профіль: 100–300 віртуальних користувачів протягом 5 хвилин) для підтвердження ефективності L1 In-Memory кешування.
- **PERF-003 (Швидкість обробки ≥ 500 вакансій за 10 хв):** Автоматизований бенчмарк на згенерованому масиві з 5 000 вакансій із вимірюванням часу роботи `ProcessRawVacanciesAsync` та `BulkUpsertAsync` у транзакції SQLite. Фіксація порогу тривалості як регресійного тесту.



## 5. Інтеграція у конвеєр CI/CD

Автоматизоване тестування повністю інтегровано у робочий процес GitHub Actions ([`.github/workflows/ci.yml`](../../.github/workflows/ci.yml)) на кожен Pull Request та пуш у гілку `main`:

1. **Lint & Static Analysis:** перевірка форматування коду `dotnet format --verify-no-changes`, виконання аналізаторів SecurityCodeScan та лінтера TypeScript MCP-сервера.
2. **Build:** компіляція всього рішення в конфігурації `Release`.
3. **Parallel Test Execution:** запуск усіх 6 тестових проектів рішення (247 тестів) із прапорцем `--collect:"XPlat Code Coverage"`.
4. **Coverage Dashboard Generation:** об'єднання Cobertura-звітів за допомогою `reportgenerator` в єдиний HTML-дашборд у каталозі `coverage-report/`.
5. **Quality Gate:** блокування злиття PR при падінні хоча б одного тесту або якщо загальне рядкове покриття опускається нижче порогу 75%.
6. **Artifact Storage:** збереження згенерованого дашборду як workflow artifact для прозорого перегляду результатів всією командою.
