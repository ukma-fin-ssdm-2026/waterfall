# Фоновий збір вакансій

`JobParserService` (src/api/Workers) раз на 30 хвилин збирає сирі вакансії й передає їх у `VacancyIngestionService`, який чистить їх і зберігає в БД. Повторний збір не дублює вакансії: запис оновлюється за парою «джерело + id на сайті».

Джерела:

1. **djinni.co**: кілька найсвіжіших сторінок `https://djinni.co/jobs/`. Увімкнено за замовчуванням.
2. **work.ua**: кілька перших сторінок усіх вакансій по всій Україні, `https://www.work.ua/jobs/?ss=1` (сама `/jobs/` — сторінка пошуку без вакансій). Увімкнено за замовчуванням, але зараз сайт не пускає сервіс (див. [Обмеження Work.ua](#обмеження-workua)).
3. **jobs.dou.ua**: офіційна RSS-стрічка вакансій `https://jobs.dou.ua/vacancies/feeds/` (50 найсвіжіших). Увімкнено за замовчуванням.
4. **JSON-дампи з цього каталогу** (резервне, офлайн): за замовчуванням вимкнено.

Сайти обходяться по черзі, і кожен — окремий виклик нормалізації: збій одного не зачіпає інші.

| Файл | Що робить |
| --- | --- |
| [`JobParserService.cs`](../../src/api/Workers/JobParserService.cs) | розклад, черга джерел, дампи |
| [`SiteCrawler.cs`](../../src/api/Workers/SiteCrawler.cs) | спільний для сайтів обхід: robots.txt, паузи, сторінки списку й сторінки вакансій, пам'ять про прочитані сторінки |
| [`RobotsTxt.cs`](../../src/api/Workers/RobotsTxt.cs) | правила robots.txt за RFC 9309 |
| [`DjinniParser.cs`](../../src/api/Workers/DjinniParser.cs), [`WorkUaParser.cs`](../../src/api/Workers/WorkUaParser.cs), [`DouParser.cs`](../../src/api/Workers/DouParser.cs) | розмітка конкретного сайту → `RawVacancy` |

## Як обходиться сайт

1. Читаємо `robots.txt`. Кожну адресу, списку чи вакансії, перевіряємо за його правилами (RFC 9309: `*` і `$` у правилах, найдовше правило перемагає, за рівної довжини — `Allow`). Якщо сайт закрив адресу, далі не йдемо.
2. Читаємо сторінки списку: 1, 2, … до ліміту з налаштувань (у DOU стрічка одна, тож сторінка лише одна). Обхід зупиняється раніше, якщо сторінка не додала нових вакансій. За межами списку Djinni знову показує першу сторінку, а Work.ua — порожню. Вакансія, яка під час обходу з'їхала на наступну сторінку, передається один раз.
3. Для кожної нової вакансії відкриваємо її сторінку: лише там є поле навичок, а на Work.ua ще й повний опис, графік, досвід і категорія. Дані зі сторінки вакансії доповнюють дані зі списку.
4. Сторінку кожної вакансії читаємо один раз: поки вакансія лишається в списку, дані з неї беруться з пам'яті. Вакансії, що зникли зі списку, з пам'яті прибираються, тож вона не росте. Після перезапуску API пам'ять порожня, і перший збір знову відкриває сторінки всіх вакансій.

### Ввічливість до сайтів (THR-11)

- Перед кожним запитом робимо паузу у 2 секунди, тобто не більше одного запиту на 2 секунди (PERF-003 дозволяє до 2 на секунду).
- За один збір читаємо по 3 сторінки списку з кожного сайту плюс сторінки нових вакансій. Перший збір після запуску — до 49 запитів до Djinni, до 46 до Work.ua і до 52 до DOU (кілька хвилин на кожен сайт), далі зазвичай кілька запитів раз на 30 хвилин.
- Сторінки вакансій відкриваються лише на самому сайті (`https`, той самий хост), навіть якщо в даних сторінки трапиться чуже посилання.
- Запити йдуть із чесним `User-Agent: WaterfallJobParser/1.0 (+https://github.com/ukma-fin-ssdm-2026/waterfall)`. Під браузер сервіс не маскується.
- Тайм-аут запиту — 30 секунд, відповідь більша за 5 МБ відкидається.
- `robots.txt` відсутній (4xx) — дозволено все; збій сервера (5xx) — сайт пропускаємо (RFC 9309).
- **Пауза після відмови.** Якщо сайт прямо відмовив — 403 (зокрема перевірка на ботів), 429 Too Many Requests чи 503 — сервіс не звертається до нього годину. Кожна наступна відмова поспіль подвоює паузу (2, 4, 8 годин…, але не більше доби), а успішний обхід її скидає. Якщо сайт сам указав `Retry-After` і просить чекати довше, чекаємо стільки, скільки просить. Випадкові збої (500, 404, тайм-аут) паузи не вмикають.
- Помилка мережі чи код 4xx/5xx на N-й сторінці списку зупиняє обхід, але вакансії з попередніх сторінок зберігаються. Сторінка без вакансій (капча, нова верстка) записується в журнал як попередження.
- Якщо не відкрилася сторінка вакансії (наприклад, 429 Too Many Requests), вакансія все одно зберігається з даними зі списку, а решту сторінок вакансій у цьому зборі сервіс не відкриває.

## djinni.co

Djinni вбудовує в сторінку списку дані для пошуковиків: масив [schema.org `JobPosting`](https://schema.org/JobPosting) у `<script type="application/ld+json">`. Їх ми й читаємо, а не верстку карток: формат цих даних задає стандарт, тож він змінюється значно рідше за HTML.

| Звідки | Поле `RawVacancy` | Перетворення |
| --- | --- | --- |
| `identifier` | `id` | `845516` → `"845516"` |
| `url`, `title`, `category` | `url`, `title`, `category` | без змін |
| `hiringOrganization.name` | `company` | без змін |
| `baseSalary` | `salary` | `2500-5000 USD`, `до 5000 USD`, `від 2000 EUR`; погодинна ставка й валюти, крім USD, EUR і UAH → без зарплати |
| `datePosted` | `posted` | Djinni пише київський час без зсуву (`2026-10-24T20:43:05.94`), тож додаємо зсув: `+03:00` влітку, `+02:00` взимку. У БД дата лягає в UTC |
| `jobLocationType`, `jobLocation` | `location` | `Віддалено`, `Україна (Київ, Львів)`, `Польща / Віддалено` |
| `experienceRequirements.monthsOfExperience` | `experience` | `Без досвіду`, `6 міс. досвіду`, `1 рік досвіду`, `5 років досвіду` |
| `employmentType` | `employment` | `FULL_TIME` → `Повна зайнятість`, `PART_TIME` → `Часткова зайнятість` тощо |
| `description` | `descriptionHtml` | текст кодується в HTML, щоб `List<T>` в описі не прийняти за тег |
| поле «Необхідні навички» на сторінці вакансії | `tags` | `TypeScript, React.js, Node.js`; частину, сховану за кнопкою «+ ще 3», теж беремо |

## work.ua

Розбір карток зроблено за зразком `WorkUaParserService` Дениса: HtmlAgilityPack і ті самі XPath-селектори біля значків `glyphicon-*`.

| Звідки | Поле `RawVacancy` | Приклад |
| --- | --- | --- |
| посилання `h2 > a` у картці (`div.job-link`) | `id`, `url`, `title` | `/jobs/8051901/` → `https://www.work.ua/jobs/8051901/` |
| підказка до посилання «…, вакансія від 19 жовтня 2026» | `posted` | `19.10.2026` |
| `span.strong-600` біля `glyphicon-hryvnia-fill` | `salary` | `17 000 – 35 000 грн`; мітка «Вища за середню» суми не має й зарплатою не вважається |
| `span.strong-600` біля `glyphicon-company` | `company` | без мітки «перевірена компанія» |
| `glyphicon-map-marker` | `location` | `Тернопіль` (без «1,0 км від центру»), `Дистанційно` |
| `div#job-description` на сторінці вакансії | `descriptionHtml` | повний опис; якщо сторінка не відкрилася — скорочений з картки |
| `glyphicon-schedule` на сторінці вакансії | `employment` | `Повна зайнятість · Стандартний графік: 5/2` |
| «Ключові вимоги і навички», пункт про досвід | `experience` | `Досвід роботи від 1 року` |
| останній пункт «хлібних крихт» | `category` | `Тестувальник`, `CRM-менеджер` |
| мітки `li.label-skill` | `tags` | `Jira, SQL, Уважність` |

Валюта за замовчуванням для Work.ua — гривня, для Djinni — долар.

### Обмеження Work.ua

Станом на 25.10.2026 Work.ua стоїть за Cloudflare, і той на сторінки вакансій відповідає сервісу `403` з перевіркою «Work.ua має перевірити безпеку вашого з'єднання… Enable JavaScript and cookies to continue». `robots.txt` при цьому віддається, і список вакансій у ньому відкритий. Сервіс записує в журнал попередження «Сторінка https://www.work.ua/jobs/?ss=1 недоступна (… сайт відмовив: 403 …)», ставить Work.ua на паузу (див. вище) і переходить до наступного джерела. Тож до Work.ua йде 2 запити спершу через годину, далі дедалі рідше, але не рідше одного разу на добу.

Обходити цю перевірку ми свідомо не стали: маскування під браузер чи проходження JS-перевірки — це обхід захисту сайту від ботів, і він суперечить THR-11. Розбір перевірено на справжніх сторінках (28 карток і 6 сторінок вакансій, завантажених вручну), тож він запрацює, щойно Work.ua пустить сервіс, наприклад після домовленості з сайтом. Щоб не звертатися до Work.ua взагалі, задайте `WorkUaPages: 0`.

## jobs.dou.ua

DOU публікує для програм RSS-стрічку `https://jobs.dou.ua/vacancies/feeds/` з 50 найсвіжішими вакансіями, а `robots.txt` дозволяє ботам і стрічку, і сторінки вакансій. Перевірки на ботів, як у Work.ua, немає.

| Звідки | Поле `RawVacancy` | Приклад |
| --- | --- | --- |
| `link` елемента стрічки | `id`, `url` | `https://jobs.dou.ua/companies/acme/vacancies/364458/` (без `?utm_source=jobsrss`) |
| `pubDate` | `posted` | `Sun, 25 Oct 2026 21:04:06 +0200` → ISO 8601 зі зсувом |
| `description` | `descriptionHtml` | повний опис; сторінка вакансії його уточнює |
| `title`: «посада в компанія, зарплата, міста» | `title`, `company`, `salary`, `location` | запасний варіант: ділимо за останнім « в », бо «в» буває й у назві посади; HTML-сутності DOU кодує тут двічі (`&amp;amp;`, `&amp;nbsp;`) |
| сторінка вакансії: `h1`, компанія в `.b-compinfo`, `.sh-info .salary`, `.sh-info .place` | `title`, `company`, `salary`, `location` | окремими полями: `Middle Java Developer`, `$2500–3000`, `за кордоном, віддалено` |
| «хлібні крихти» «Всі вакансії / Java / …» | `category` | `Java`, `QA`, `Design` |
| `.vacancy-section` | `descriptionHtml` | повний опис вакансії |

Окремого поля навичок на DOU немає, тож вакансії DOU лишаються без навичок. Валюта за замовчуванням — долар. Стрічку читаємо через `XmlReader` із вимкненими DTD і зовнішніми сутностями (захист від XXE).

Живий запуск 26.10.2026: 50 вакансій збережено, 0 відкинуто; зарплата в 10, категорія в усіх.

## Навички

Навички беремо **лише з окремого поля на сайті**: «Необхідні навички» на Djinni і мітки навичок на Work.ua (на DOU такого поля немає). Роботодавець заповнює його за бажанням: на живому djinni.co (жовтень 2026) воно було в 13 з 45 вакансій, на Work.ua — на всіх 6 перевірених сторінках. Якщо поля немає, `RawVacancy.Tags` — `null`, а в БД і API — порожній список: з назви чи опису навички не вгадуються.

У БД навички лежать як JSON без `\u`-екранування (`["Комунікація","C/C++"]`), щоб їх знаходив пошук каталогу.

## JSON-дампи (офлайн)

Якщо в `Ingestion:RawDataDirectory` вказано каталог, сервіс після сайтів читає всі файли `*.json` з нього. Так можна працювати без мережі або імпортувати вакансії, зібрані іншим інструментом. Щоб увімкнути демонстраційний дамп:

```bash
# PowerShell: $env:Ingestion__RawDataDirectory = "../../data/raw"
Ingestion__RawDataDirectory=../../data/raw dotnet run --project src/api
```

### Формат дампу Djinni

```json
{
  "source": "djinni",
  "jobs": [
    {
      "id": "720001",
      "url": "https://djinni.co/jobs/720001-senior-net-developer/",
      "title": "Senior .NET Developer",
      "company": "Kvitka Software",
      "salary": "$3500-4500",
      "location": "Kyiv, Remote",
      "posted": "2 дні тому",
      "experience": "5 років досвіду",
      "employment": "Full Remote",
      "category": ".NET",
      "descriptionHtml": "<p>Опис вакансії з HTML-тегами</p>",
      "tags": "C#, .NET, PostgreSQL"
    }
  ]
}
```

| Поле | Обов'язкове | Що з ним відбувається |
| --- | --- | --- |
| `source` (на рівні файлу) | так | поки що лише `djinni`; поле `source` в окремій вакансії ігнорується |
| `id` | так | рядок; разом із джерелом — ключ для оновлення |
| `url` | так | лише `https://djinni.co/...`; параметри після `?` відкидаються |
| `title` | так | зайві пробіли прибираються; щонайменше 2 символи (QA, PM) |
| `descriptionHtml` | так | HTML → текст, `<script>` і `<style>` видаляються |
| `salary` | ні | `$3500-4500`, `від $2000`, `до $2500`, `€2500–3500`, `1500 USD`; погодинна ставка й «за домовленістю» → без зарплати; валюта за замовчуванням — USD |
| `posted` | ні | `сьогодні`, `вчора`, `3 дні тому`, `5 годин тому`, `10 хв. тому`, `08.10.2026`, ISO 8601; інше — дата збору |
| `company`, `location`, `category` | ні | порожнє → «Не вказано» / «Інше» |
| `experience`, `employment` | ні | зберігаються як є |
| `tags` | ні | рядок через `,` `;` або `\|`; дублікати прибираються; порожнє → навичок немає |

### Демонстраційний дамп

`djinni-sample.json` — **вигадані** дані: компанії й ідентифікатори не справжні. З 12 записів 10 зберігаються, а 2 навмисно відкидаються з поясненням у журналі: запис без назви посади і запис із посиланням на сторонній домен (фішингова вакансія з моделі загроз, THR-03).

Тому за замовчуванням дампи вимкнено: вигадані вакансії не повинні змішуватися зі справжніми. Файл лишається для тестів і офлайн-демонстрації.

## Налаштування

Секція `Ingestion` в `src/api/appsettings.json`:

| Параметр | Значення | Призначення |
| --- | --- | --- |
| `Enabled` | `true` | вмикає фоновий збір |
| `Interval` | `00:30:00` | як часто повторювати збір |
| `DjinniPages` | `3` | скільки перших сторінок djinni.co читати за раз (по 15 вакансій); `0` — не звертатися до сайту |
| `WorkUaPages` | `3` | скільки перших сторінок усіх вакансій work.ua читати за раз (по 14 вакансій); `0` — не звертатися до сайту |
| `DouPages` | `1` | читати RSS-стрічку jobs.dou.ua (одна сторінка, 50 вакансій); `0` — не звертатися до сайту |
| `RequestDelay` | `00:00:02` | пауза перед кожним запитом до сайту |
| `RawDataDirectory` | `""` | каталог з дампами відносно `src/api`; порожній — дампи не читаються |

Щоб збір не можна було зробити нав'язливим ні в `appsettings.json`, ні змінними середовища, API перевіряє налаштування на старті (`IngestionOptionsValidator`) і не запуститься, якщо `Interval` менший за 10 хвилин, `RequestDelay` менший за 0,5 с (PERF-003: не більше 2 запитів на секунду) або кількість сторінок поза межами 0–10. У журналі буде пояснення, наприклад «Ingestion:Interval має бути не менше 10 хв, а задано 00:00:10».
